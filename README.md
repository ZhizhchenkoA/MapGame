# Созвездия — игра на графе

Статический сайт для GitHub Pages с картой из [svg-dashboard](https://github.com/iuriigrishin/svg-dashboard). Карта содержит 43 территории. Соседство рассчитано по SVG-контурам и хранится в `site/graph.json`.

## Публикация на GitHub Pages

1. Загрузите проект в GitHub-репозиторий, ветка `main`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions** и сохраните настройку. Pages должен быть включён для репозитория.
3. Повторно запустите workflow `Deploy GitHub Pages` в Actions или отправьте новый commit. Он публикует папку `site`.

Предыдущая версия workflow падала на `actions/configure-pages@v5` с `Get Pages site failed: Not Found`. Для готового статического сайта этот шаг не нужен, и он удалён. Однако **первичное включение Pages всё равно необходимо**. Параметр `enablement` у `configure-pages` требует отдельный токен с правом настройки Pages; обычного `GITHUB_TOKEN` недостаточно. Если деплой теперь сообщает, что Pages не включён, проверьте шаг 2 и права доступа к репозиторию.

## Таблица и несколько игр

1. Создайте Google Таблицу и откройте **Extensions → Apps Script**.
2. Вставьте `site/apps-script/Code.gs`. В **Project Settings → Script properties** добавьте `JURY_PIN` с длинным случайным значением.
3. Запустите `setup()` вручную и разрешите доступ. Он создаёт служебные листы `Games`, `Events` и первую игру `J1 vs J2`, а для существующих игровых листов обновляет судейские поля. Повторный `setup()` не удаляет существующие игры. Если уже есть лист старой версии `State`, первый запуск перенесёт его состояние в `J1 vs J2`; старый лист останется как резервная копия.
4. **Deploy → New deployment → Web app**: Execute as **Me**, Who has access: **Anyone**. Скопируйте URL `/exec`.
5. На сайте откройте «Настройки», вставьте URL и PIN. URL сохраняется в этом браузере, PIN остаётся только в памяти вкладки. Посетители без PIN видят счёт и карту.

Кнопка **«Ссылка для игроков»** копирует адрес вида `https://<имя>.github.io/<репозиторий>/?api=<URL-Apps-Script>&game=<имя-игры>`. Ребёнок откроет нужную игру без настройки URL. PIN жюри в ссылку не включается. Адрес веб-приложения доступен обладателям ссылки только для чтения; право изменять игру по-прежнему требует PIN или доступ редактора Google Таблицы.

Кнопка **«Новая игра»** создаёт отдельный лист для противостояния и добавляет вкладку на сайте. Кнопка **«Удалить игру»** видна только после ввода PIN жюри; она требует подтверждения и навсегда удаляет выбранный игровой лист. Запись об удалении остаётся в `Events`. Можно вести несколько игр одновременно; действия и счёт изолированы по листам. Лист игры содержит таблицу задач, попыток, сбросов, подсказок и итоговый счёт. `Games` перечисляет игры, `Events` хранит общий журнал с названием игры. Ячейка `A2` каждого игрового листа содержит машинное состояние: **не редактируйте её вручную**.

### Названия созвездий

Названия задаются в массиве `CONSTELLATIONS` файла `site/constellations.js`: индекс массива равен номеру области на карте (1–43). №3 «Малый Конь», №19 «Малый Пёс» и №43 «Малая Медведица» уже заполнены. Для остальных номеров впишите названия вместо пустых строк. После изменения файла отправьте сайт в GitHub; повторно развёртывать Apps Script не нужно. Если у вас остался лист `Names` от прежней версии, он больше не используется и может служить резервной копией.

### Управление прямо в Google Таблице

- `B3`: отметьте флажок, чтобы начать игру.
- В строках **«Взята»** отметьте новую соседнюю карточку. Стартовые №3 и №19 уже выданы.
- В строках **«Попытка 1–3»** выберите `×` (неверно) или `✓` (верно) из списка. Заполняйте попытки по порядку. Для обычных задач третья попытка недоступна.
- В строках **«Сброс»** и **«Подсказка»** поставьте флажок. Подсказка разрешена после первой ошибки.
- Недопустимые действия откатываются до сохранённого состояния; причина ошибки появляется в примечании к ячейке. Счёт и цвета обновляются автоматически. Редактировать лист должны только члены жюри.

Судейская таблица на сайте напоминает присланный образец: задачи по колонкам, строки «Взята», «Результат», «Сброс», «Подсказка» для каждой команды. Нажатие на колонку выбирает территорию; действия выполняются в панели под картой.

После изменений Apps Script создайте **новую версию deployment** через Manage deployments → Edit → New version. Старый URL `/exec` обычно сохраняется.

Жюри принимает ответы вне сайта и отмечает результат на сайте или в Google Таблице. Оно выбирает новые соседние карточки после освобождения места, решает, можно ли дать подсказку, и отмечает сброс. Одновременные действия сериализуются `LockService`; первое подтверждённое решение захватывает территорию. Сайт проверяет изменения примерно каждые 3 секунды после завершения предыдущего запроса. POST выполняется в `no-cors`, поэтому при отказе скрипта браузер не видит текст ошибки; проверяйте результат по обновлённому листу и `Events`.

## Правила

- Стартовые карточки №3 и №19; 3 попытки на старт, 2 на остальные.
- Не более 3 карточек одновременно; брать можно только области, смежные с захваченными. Жюри выбирает новую карточку после сдачи или сброса.
- Сброс и исчерпание попыток запрещают повторную выдачу данной команде. Территория становится серой только после отказа обеих команд; до этого доступна сопернику.
- Захват снимает карточку у соперника. №1–27 дают 5, №28–42 — 8, №43 — 12 баллов. Подсказка после первой ошибки стоит 2 балла.
- Ограничения по времени нет. Игра завершается, когда у обеих команд нет карточек и доступных территорий.

Перед официальной игрой проверьте спорные соприкосновения контуров по углам. В исходном репозитории не найден файл лицензии на карту; условия её публикации следует уточнить у автора.
